# 2026-06-16 Evaluation Record MVP Module Description

## This time's goal

A new evaluation record MVP module is added, and the UniApp WeChat applet front-end is given priority. The design of the mini program evaluation page refers to the previous H5 growth education style. The backend is connected to the CRMEB login authentication and real interface, and the backend provides a list of evaluation records and detailed viewing.

## database

New table:

- `eb_education_assessment_records`

Fields:

- `id`
- `uid`
- `nickname`
- `mobile`
- `score`
- `result_text`
- `answers_json`
- `created_at`
- `updated_at`

The SQL file contains two sections, `-- up` and `-- down`. The background menu uses `unique_auth` for idempotent insertion and does not rely on fixed menu IDs; newly inserted menus will be written with `mark = education-assessment-mvp`. When rolling back, only the menu data that matches both `unique_auth` of this module and the `mark` will be deleted to avoid accidentally deleting the menu that originally existed in the target library; then delete the `eb_education_assessment_records` table.

## backend interface

Mini program submission interface:

- `POST /api/education/assessment_records`
- User login authentication is required and is protected by CRMEB `AuthTokenMiddleware`.
- `score` is allowed to be empty; the value must be passed as a number.
- `answers_json` allows passing JSON objects or legal JSON strings. Illegal JSON will be rejected.

Backend interface:

- `GET /adminapi/education/assessment_records`
- `GET /adminapi/education/assessment_records/:id`
- Backend login authentication is required.

## Mini program front end

Evaluation page:

- `src/CRMEB/CRMEB-master/template/uni-app/pages/assessment/index.vue`

Interface file:

- `src/CRMEB/CRMEB-master/template/uni-app/api/education.js`

Page entry:

- `src/CRMEB/CRMEB-master/template/uni-app/pages.json`
- `src/CRMEB/CRMEB-master/template/uni-app/config/mvp.js`
- The MVP entry on the homepage contains "Entry Evaluation" and jumps to `/pages/assessment/index`.

Current mini program evaluation page capabilities:

- 3 MVP review questions.
- Scores are calculated in real time after selecting an answer.
- When the answer is not completed, the placeholder status of "Generate a portrait after completing the assessment" will be displayed to avoid giving a formal conclusion in advance.
- After answering, the assessment progress, current score, ability portrait, result label and recommended growth plan are displayed.
- The real CRMEB interface is called when submitting.
- When not logged in, the CRMEB applet request package will be used and the login will be automatically redirected.
- After successful submission, "Evaluation record has been saved and the results can be viewed in the background" will be displayed.

## Interface joint debugging example

The user submits the evaluation record:

```bash
curl -X POST "http://127.0.0.1:8080/api/education/assessment_records" \
  -H "Content-Type: application/json" \
  -H "Authori-zation: Bearer <USER_TOKEN>" \
  -d "{\"score\":80,\"result_text\":\"steady growth type\",\"answers_json\":{\"result\":{\"title\":\"steady growth type\",\"text\":\"the child already has a good foundation for independent learning\",\"tags\":[\"stable focus\"]},\"answers\":[{\"question_id\":\"focus\",\"question\":\"which focus state is closer when the child completes learning tasks?\",\"answer\":\"can complete steadily\",\"value\":\"stable\",\"score\":30}]}}"
```

Backend list:

```bash
curl "http://127.0.0.1:8080/adminapi/education/assessment_records?page=1&limit=20" \
  -H "Authori-zation: Bearer <ADMIN_TOKEN>"
```

Backstage details:

```bash
curl "http://127.0.0.1:8080/adminapi/education/assessment_records/<ID>" \
  -H "Authori-zation: Bearer <ADMIN_TOKEN>"
```
